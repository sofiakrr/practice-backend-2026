## Чекпоинт 3 — Бронирование

### Что реализовано

- Создание бронирования (дата, время начала, время окончания)
- Проверка пересечений по времени (ключевая бизнес-логика)
- Запрет бронирования на прошедшую дату
- Отмена бронирования пользователем (только своё)
- Отмена бронирования администратором (любое)
- Список бронирований: user видит свои, admin — все
- Журналирование бизнес-операций (создание, отмена, отказы)

---

### Эндпоинты бронирования

| Метод | URL | Кто может | Описание |
|---|---|---|---|
| GET | `/api/bookings` | Авторизован | User — свои, admin — все |
| POST | `/api/bookings` | Авторизован | Создать бронирование |
| DELETE | `/api/bookings/{id}` | Авторизован | User — своё, admin — любое |

---

### Бизнес-правила

- Нельзя забронировать столик на **прошедшую дату**
- Нельзя создать бронирование если **время пересекается** с уже активным
- Нельзя отменить **уже отменённое** бронирование (повторная отмена)
- Обычный пользователь **не может отменить чужое** бронирование
- Администратор **может отменить любое** бронирование

---


### Журналирование

Все бизнес-операции логируются в `storage/logs/laravel.log`:

| Событие | Уровень | Что записывается |
|---|---|---|
| Бронирование создано | `info` | user_id, booking_id, ресурс, дата, время |
| Конфликт времени | `warning` | user_id, resource_id, дата, время, причина |
| Бронирование отменено | `info` | user_id, booking_id, роль |
| Попытка отменить чужое | `warning` | initiator_id, booking_id, owner_id, причина |
